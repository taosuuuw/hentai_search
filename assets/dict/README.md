# assets/dict · 黑话词典数据层

本目录是**纯数据**，不含判定逻辑。判定与渲染由 `assets/js/dict-hint.js`（`HS.dict`）负责，
挂载点由 `assets/js/app.js` 负责，实时建议由 `assets/js/suggest.js` 负责。

| 文件 | 作用 |
| --- | --- |
| `core.js` | **核心层**：公共黑话（跨 IP 的题材 / 谐音 / 作品俗称）。传统 `<script>`，首屏同步就绪 |
| `ip/index.json` | **包清单**：登记每个包的 `id` + `anchors`（= 懒加载触发词）。**懒加载的唯一触发来源**，首次检索才拉 |
| `ip/<id>.json` | **IP 分包**（当前 24 个：游戏 6 + 动画 18）。按锚点门控，懒加载。逐包明细见仓库根 `DICTIONARY-INDEX.md` |

所有词条**只用于产出提示，绝不参与查询改写**：用户不点提示，发往上游的查询串一个字节都不会变。
词典任何状态（未加载 / 404 / JSON 损坏 / 版本不认识）都不得影响检索行为。

### 放置位置是否合适 —— 结论：合适，不需要移动

这个位置是**被引擎写死的**，不是习惯选择。五条可验证的理由：

1. **路径写死在引擎里**：`assets/js/dict-hint.js` 有常量 `const IP_DIR = 'assets/dict/ip/'`，
   `fetchPkg()` 只会去两个地方取包 —— `<gatewayBase>/<id>.json` 或 `IP_DIR + <id> + '.json'`。
   放到别处 = 永远拉不到。
2. **包名即文件名，三者必须逐字一致**：`fetchPkg(id)` 实际请求的是
   `IP_DIR + encodeURIComponent(id) + '.json'`（清单里的 `file` 字段只是元数据，引擎不读它）。
   所以 **文件名 / 包内 `id` 字段 / 清单里登记的 `id`** 必须完全相同；惯例是全小写 ASCII，
   可以带连字符（现状里就有 `blue-lock` / `jujutsu-kaisen` / `dress-up-darling` / `oshi-no-ko` 等）。
3. **必须在 `assets/` 之下**：网关的静态服务与"直接双击 `index.html`"这条退化路径都以 `assets/` 为
   web 根。放到 `docs/` 或仓库根会 404 / 跨域。
4. **没有任何打包白名单**：`start-engine.sh` / `start-engine.cmd` / `tools/start-gateway.ps1` /
   `tools/gateway.js` 都没有文件清单，发布走 git 与手工打包 —— 新增文件**不会被漏掉**，
   也不需要改动任何脚本。
5. **不违反 C3**：`assets/` 下确实可被用户 `fetch` 到，但 C3 已明确"不防扒、只要求用户看不见"，
   所以这不是风险。

> **唯一真正的坑不在 `ip/` 目录里，而在触发词登记**：新增包只放 `ip/<id>.json`、
> 不同步更新 `ip/index.json`（清单）里该包的 `anchors`，包就永远不加载 —— 详见 §3。

## 1. 判定契约（已逐行核对 `dict-hint.js`，不要凭猜测改动条目字段）

### 1.1 条目字段

```jsonc
{ "from": "小火龙",                      // 必填。用户可能输入的表面形式
  "to":   { "character": "ifrit" },      // 必填。对象，且只能有一个键
  "kind": "character",                   // 与 to 的键一致
  "label": "伊芙利特",                    // 给人看的中文
  "conf": 0.95,                          // 0–1 先验置信度，**决定档位**
  "ambiguous": false,                    // true = 永不主动提示
  "why": "伊芙利特会喷火，故称小火龙" }     // 必填。显示在 chip 的 title / aria
```

`validatePkg()` 只强制 `from` 为非空字符串、`to` 为对象；其余字段缺失会静默取默认值
（`conf` 缺省 0.5 → 必定落兜底档）。**所以 `conf` 必须显式写。**

### 1.2 档位（`HS.dict.tier`）

| 档 | 条件 | 出现位置 |
| --- | --- | --- |
| `active` | `!ambiguous` **且** `conf >= 0.85` **且** `hintQuery` 非空 | 检索一开始就出泡泡（每次最多 2 条） |
| `low` | 其余全部 | **只在 0 结果时**才出 |

`hintQuery` 由 `hintQueryFor(to, kind)` 推导，规则：
`to.concept` → `HS.CONCEPTS` 里该 key 的 `zh`；`to.genre` → `HS.GENRES` 的 `label`；
`to.series` → `HS.SERIES` 里的规范写法（**不在表里就没有 hintQuery**）；
`to.character` → **原值直接使用**；其它键（如 `to.term`）→ 空串。

- **有 `hintQuery`** → 渲染成可点 chip，`data-q` 交给 `app.js` 既有的 `[data-q]` 委托，
  点击后**只替换被点中的那一段**（多片段输入不会丢词）。
- **没有 `hintQuery`** → 渲染成**不可点击的说明**（带「可能」标记）。`to.term` 走的就是这条，
  所以本词典里 40 条玩法 / 阵营 / 世界观词条是无害的纯说明。

> **`to.concept` 指向的 `HS.CONCEPTS`（2026-09 同步）**：那是**引擎侧**（`assets/js/dict.js`）
> 的跨语言同义词组表，现有 **128 组**（2026-09 本轮从 122 拆出 `gangbang` / `femdom` /
> `maledom` / `femsub` / `malesub` / `giantess` 六组）。两条结构性事实：
> ① **有一批 CONCEPTS 别名是「死别名」** —— `core.js` 的 `classifyQuery` 里 `HS.GENRES` 先于
> `HS.CONCEPTS` 命中，实测 **91 条**别名（90 条被 GENRES 抢走，如 `巨乳` / `触手` / `loli` /
> `扶他` / `女攻め`；1 条被系列词典抢走：`精神崩坏` → 系列 `崩坏`）拿它自己的写法去查**不会**
> 返回那个概念组。这只影响「查询分类」，**不影响 `to.concept`**：`hintQueryFor` 直接读该组的 `zh`。
> ② 两条不变量由 `node tools/concept-check.js` 的 ⑧ 看门：**跨组重复别名 = 0**、
> 三槽（zh / en / ja）值都能被 `conceptOf` 找回本组（**死槽 = 0**）—— 加组时别打破它们。

### 1.3 锚点门控（**最容易踩的坑**）

`lookup()` 里触发词（锚点）有三个来源，作用不同：

- **`ip/index.json` 清单里各包的 `anchors`**：**主路径，唯一决定懒加载**。
  只有它命中，`pending` 才会带上 `arknights`，app 才会去 `load()`。
- **`core.js` 的 `anchors` 对象**（`{'触发词': '包 id'}`，实测 **25** 条）：清单缺失 / 404 / 坏 /
  尚未就绪时的**回退注册表**，命中同样能触发加载。
- **包内 `arknights.json` 的 `anchors` 数组**：**只在包已经加载之后**才参与资格判定。
  它**不会**触发加载。

结论：一个词只写进包内 `anchors`、没同步进清单（或 `core.js` 的回退映射表），在**全新会话**里单独搜它
**永远不会加载本包，也就永远不会出提示**。详见下面第 3 节。

### 2.1 同名冲突的四条规则（这一节是踩过坑换来的，别再踩）

引擎的 `markSameFragmentConflicts` 按 **`from` × 包** 计数：同一个 `from` 出现在 **≥2 个层/包**里，
这几条会被一起标成 `ambiguous`，**一起从主动档掉到兜底档**。据此有四条规则：

| # | 规则 | 踩过的坑 |
| --- | --- | --- |
| 1 | **`entries` 绝不能与 `core.js` 已有的 `from` 同名** | `arknights` 包里写过 `舟游`，而 `core.js` 已有该条 → 两条一起降档。已删包内那条 |
| 2 | **`anchors` 可以与 `core.js` 的条目重合**（锚点不产生命中，只触发加载） | `崩铁` / `星铁` 是 `core.js` 的**条目**，本包同时把它们留在 `anchors` 里 —— 这是**正确**的，包内 `entries` 刻意不写它们，实测 `崩铁` 仍是主动档 |
| 3 | **厂商名不进 IP 包**，它天然跨包 | `米哈游` 曾同时写在 `genshin` 与 `zenless` → 一起降档。已从两包删除（`米忽悠` 一并删）。厂商名属于 `core.js` 公共层，**建议维护者把 `米哈游 / 米忽悠 / 库洛 / 鹰角` 补进 `core.js`**；目前只有 `arknights` 保留 `鹰角`（单 IP，未冲突） |
| 4 | **包内同名是允许的**，那是同一片段的双重解释 | `arknights` 的 `蒂蒂` 同时指向斯卡蒂与温蒂，两条都已 `ambiguous: true`，引擎按 `span + to` 去重后各自保留 |

**跨包同名要分两种情况看**（静态扫描会一律报出来，但运行期行为不同）：

- `空`（`arknights` 的空 + `genshin` 的主角）：两包**都没有** `空` 这个锚点 → 查询「空」时无锚点命中，
  于是走兜底路径放开所有已加载包 → **两条都出现并都被标 ambiguous**。这是真实双解释，属预期。
- `真理`（`arknights` 的 Istina + `starrail` 的真理医生）：**2026-09-21 收紧锚点后，两包都不再有
  `真理` 这个锚点**（原先把 `真理` 当锚点会让「含真理二字的任何查询」白拉 `starrail`，见 §4(b-2)），
  所以查询「真理」时两个包都不会被门控放行 —— 全新会话里**一条提示都不出**（返回 `pending=[]`），
  与 `空` 同属"无锚点命中 → 不留提示"这一类，只是不再有包被误拉。
  想查真理医生，用仍然登记的 `真理医生`（或 `starrail` 的其它锚点，如 `景元` / `牢景`），
  包加载后 `真理` 的词条照常会出：
  `真理医生` → `pending=["starrail"]` → 加载后 `真理 → 真理医生【dr. ratio】` 也在命中列表里。
  静态扫描报的"跨包同名"在运行期并不成立，这是**锚点门控在正常工作**，不是数据丢失。

> 想验证某条到底怎么走，别靠静态扫描，直接用引擎跑：见 §7 第 5 步的自测脚本。


### 2.1 我刻意采用的 `conf` 约定（重要，改档位只需改这一个数）

| 类别 | `conf` | 档位 | 理由 |
| --- | --- | --- | --- |
| **真黑话 / 外号**（小火龙、德狗、老猞猁…） | 0.85–0.95 | `active` | 这就是本功能的意义：用户输入黑话时**立刻**告诉他理解成了谁 |
| **官方中文名 → 英文检索名**（伊芙利特 → ifrit…） | 0.78–0.80 | `low` | 中文名本身已是合格查询，不该每次都弹提示；**只有 0 结果时**才提示「试试 ifrit」——而那正是最需要它的时刻 |
| **多义 / 通用词**（叔叔、蒂蒂、42、富婆、法官、大哥…） | 0.55–0.82 + `ambiguous: true` | `low` | 通用词绝不能主动劫持查询，只在 0 结果时作为可能性列出 |

> 若日后想让「官方中文名 → 英文名」也主动提示，把那些条目的 `conf` 从 0.8 提到 **0.85** 即可，
> 不需要改代码。反之想让某个外号变保守，加 `ambiguous: true` 即可。

### 2.2 英文检索名一律写成 ASCII

`to.character` 会被**原样填进搜索框**，而引擎的主力源（nhentai / E-Hentai / Danbooru / Hitomi /
MangaDex）用的是英文标签，所以：

- 玛恩纳 → `mlynar`（**不是** `Młynar`）
- 鸿雪 → `pozemka`（**不是** `Pozëmka`）
- 变音符一律去掉，ASCII 撇号保留（`kal'tsit`、`ch'en`、`ho'olheyak`）——去掉撇号反而对不上标签。

## 3. 触发词登记：清单是主路径（**机制已于 2026-09-21 变更为清单驱动**）

引擎是**清单驱动**的 —— `dict-hint.js` 里有 `MANIFEST_FILE = 'index.json'` /
`MANIFEST_URL = IP_DIR + MANIFEST_FILE`。"该去加载哪个包"**以 `assets/dict/ip/index.json` 为准**；
`core.js` 的 `anchors` 映射表**降级为清单缺失 / 404 / 坏 / 未就绪时的回退方案**。

| 机制 | 状态 | 当前情况 |
| --- | --- | --- |
| `assets/dict/ip/index.json` 的 `packages[].anchors` | **主路径** | **24/24 个包全部登记完毕**（6 游戏 + 18 动画，共 **1021** 条锚点，与各包内 `anchors` 逐条一致） |
| `assets/dict/core.js` 的 `anchors` 映射表 | 回退 | 实测 **24 条**（`arknights` 12 + `genshin` 6 + `starrail` 3 + `zenless` 1 + `wuwa` 2；其中 5 个包有映射，不重复计数共 24）。2026-09-21 收紧锚点时**同步删掉了 `zzz` → `zenless`** 这一条，其余不动 |

**当前没有缺口。** 早先那一版"动画包还没登记进清单"的说法已经作废：
清单现在是 24/24 全覆盖（包数 24 / 锚点 1021，见 `DICTIONARY-INDEX.md` 第四节）。

> **维护约定**：**新增或修改一个包之后，必须重新生成 `index.json`** ——
> `packages` 按 `id` 字典序，`anchors` 从 `ip/<id>.json` 里**逐字复制**。
> 为什么必须：浏览器拿不到目录列表，清单里没有的包**不会自愈**，
> 表现是"不报错、不下载、不出提示"的**静默失效**（R9 在清单机制下的形态）。
>
> 各包文件里的 `_anchorsNote` 一度写着"同步进 `core.js` 的 anchors 映射表"，
> 那是清单机制上线前的说法。**现在一律以 `index.json` 为准**，各包的
> `_anchorsNote` 已按这个约定改写（见 §3 末与各包 `_anchorsNote`）。
>
> 清单还有一条自我保护（`index.json` 的 `_note` 有说明）：`anchors` 为**空数组**的包，
> 引擎会在首次检索的空闲时机低优先预取它（`PRE_FETCH_MAX = 3` / 会话），
> 避免"新增包忘了登记触发词就永久失效"。**目前 24 个包都有锚点，这条兜底暂时用不上。**

两条叠加的后果是 —— **任何包含该词的查询都会白拉一个包**。这与之前已经处理过的
`驴子` / `煌` / `锏` 是同一类问题：

- `一花` / `二乃`：单名简称，`一花` 还是常用词（一花一世界），与已经排除的
  `三玖` / `四叶` / `五月` 处理口径也终于一致了（五姐妹现在**五个单名都不作锚点**）；
- `修女` / `护士长` / `锅巴` / `公子` / `仆人` / `先蒂` / `警员`：称谓或通用外号，
  任何语境里都可能是普通词。

因此不再出提示**（`pending=[]`、无 HTTP 请求；词条本身还在，包被别的锚点加载后照常参与判定）：

  `鹰角` → `hypergryph`、`护士长` → `sigewinne`(希格雯)、`仆人` → `arlecchino`(阿蕾奇诺)。
  它们**在删除名单里，已按维护者决定删除**；如果希望这几个角色重新可达，见下方"如何恢复"。
  **2026-09-21 四次修订已按该法恢复两个**：官方名 `希格雯` / `阿蕾奇诺` 补进 `genshin` 的
  `anchors`（而不是把通用称谓加回来）→ `sigewinne` / `arlecchino` 恢复可达；
  `鹰角` 按"厂商名不加"的决定保持不登记，`hypergryph` 仍不可达。
- **两个词判定的依据**（本轮额外判断）：`空洞` / `代理人` 都在 `zenless` 的 `entries` 里
  （分别 `→ term: hollow` / `→ term: agent`，都标了 `ambiguous`），
  但它们**都不是任何角色的唯一常用名**：`空洞` 是该作的世界观名词（也是通用词），

  **词条保留、不作触发词**。"保留词条"对它们自动成立（词条与锚点是两套东西，见 §1.3）。

## 5. 已知小瑕疵

1. **短词在长词内部误命中**：`企鹅物流` 会同时命中 `企鹅`（麦哲伦）。因为两者都是 `low` 档，
   只影响 0 结果时的说明列表，不影响有结果的正常检索。若介意，把 `企鹅` 的 `conf` 再压低或删除该条。
2. **玩法词条价值有限**：`肉鸽 / 公招 / 专三 / 精二` 等 14 条 `kind: "term"` 是**不可点击的说明**，
   只在 0 结果时出现，对「找本子」帮助有限。留着是为了词典完整；不需要可直接删掉整块，
   不影响任何代码。
3. **终末地有一条推断项**：`秋栗 → akekuri` 是用「四星 / 电磁」在官方中英名单之间**排除法推得**的，
   未拿到直接的双语来源，因此 `conf` 压到 **0.7 + `ambiguous: true`**（只会在 0 结果时出现）。
   拿到权威对照后请把 `conf` 提到 0.8 并去掉 `ambiguous`。
4. **终末地只覆盖 23 名角色**（24 条 `character` 词条，其中 `陈千语` / `千语` 指向同一人），见 §6.2；其余 9 名因无法确认中文名而**整条未收**——绝不猜造英文名。
5. **`神里绫华` 会同时命中 `神里`**（两者都指向绫华）。因为 `span` 不同，引擎会保留两条提示，
   文案重复但都正确，且都属 `low` 档，只影响 0 结果时的列表。若不想要，删掉 `神里` 这一条即可。
6. **`洁尔佩塔`（终末地）与 `安洁莉娜`（明日方舟）字形相近**，已因此把 `洁尔佩塔` 压到
   `conf 0.78 + ambiguous`，避免用户搜错时被高置信误导。
7. **短词在多字名内部再误命中**：`卢姥爷` 会同时命中 `爷`（旅行者）、`陈千语` 会同时命中 `千语`
   （都正确）。同样只影响 0 结果时的列表，不影响正常检索。
8. **终末地的官方名没有走主动档**：`佩丽卡 / 陈千语 / 别礼 / 莱万汀 / 卡缪` 目前都是 `conf 0.8`
   （→ 兜底档，只在 0 结果时提示），全包只有 `管理员`（`conf 0.85`）是主动档。
   早先的设想是"终末地刚上线、英文标签站命中率低，直接告诉你检索名更有用"，但数据里没有落实；
   若想让这几个官方名主动提示，把它们提到 `conf 0.85` 即可（不需要改代码）。
9. `kind: "term"` 是本次引入的新 kind（引擎对未知 kind 是安全的：只是没有 `hintQuery`）。
   若日后想让阵营词也可点击（如 `企鹅物流 → penguin logistics`），需要引擎侧支持
   `to.tag` 或把阵营名加进 `NS.SERIES`，属接入方决定。

> 而 `zenless` 与 `wuwa` 的双语表**抓不到** —— 中文维基被网络限制挡住（`fetch failed`）、
> 巴哈姆特的中英日韩对照表同样被挡、萌娘百科的《鸣潮/译名对照表》返回被截断只剩标题。
> 因此这两包的中英映射依赖**官方英文角色页 + 英文 wiki 名单**，`conf` 一律压到
> **0.7–0.82（全部落在兜底档，只在 0 结果时出现）**，属于"方向性建议"而非权威对照。
> 拿到权威双语表后请逐条复核并把 `conf` 提到 0.8（去掉 `ambiguous`）。

### 6.2 覆盖与缺口

| 包 | 覆盖 | 缺口 |
| --- | --- | --- |
| `arknights` | 367 条 ≈ 170 名干员 + 剧情角色（官方中文名 + 外号）+ 组织 / 国家 / 玩法 | 近年新干员（如 Mon3tr、Bellone、Entelechia 等）、极冷门 4★ |
| `starrail` | 109 条 = 66 名角色（含全部五星主力与四星）+ 4 系列名 + 20 条设定 / 玩法。**外号覆盖最好的新包** | 2026 年后的新角色；部分早期四星 |
| `genshin` | 214 条 ≈ 90 名角色（含七神、愚人众、各版本主力）+ 20 条设定 / 抽卡术语 | 2026 年新角色、部分四星；外号以 2024 年游侠表为准，更新的梗需补 |
| `zenless` | 56 条 = 40 名角色 + 16 条设定 / 用语 | **外号很薄**（只有 3 条）；且中英映射**无权威双语来源**（见 §6.1 注）；2026 年新代理人未收 |
| `wuwa` | 59 条 = 44 名角色 + 15 条设定 / 用语 | **外号最薄**（只有 3 条）；中英映射同样缺权威来源；釉瑚 / 陆赫斯 / 爱弥斯 等未能确认英文名，**未收** |
| `endfield` | 44 条 = 23 名角色 + 20 条设定 / 玩法 | **9 名角色未收**：Alesh / Avywenna / Ember / Lifeng / Liino / Purrchena / Rossi / Tangtang / Zhuang Fangyi —— 未能确认其中文名 |


**终末地那 9 名的补录方法**（拿到权威对照后照做即可）：
把 [Endfield Talos Wiki 的干员表](https://endfield.wiki.gg/wiki/Operator/List)（英文 + 星级 / 职业 / 属性）
与 [CEP 干员表](https://end.canmoe.com/zh-CN/wiki/characters)（中文 + 星级 / 职业 / 属性）按
**星级 + 职业 + 属性三项全等**配对。例：`Ember` 是「6★ 重装 · 灼热 · 双手剑」，
就在中文表里找同为「6★ / 重装 / 灼热」的那一条。配对成功后按 §7 的步骤补 `entries` 与 `anchors`。
**若三项仍不足以唯一确定，就不要收**——错映射比缺失更糟。

**通用补录规则**：往 `entries` 里加词条的同时，若该词应作为触发词，
**必须**同步加进包内 `anchors` 数组**并重新生成** `ip/index.json`（§3）。

## 7. 再加一个 IP 包的步骤

1. 新建 `ip/<id>.json`，`schema` 必须是 **1**（`validatePkg` 版本不认就整包丢弃）。
2. `entries` 每条至少给 `from` / `to` / `kind` / `label` / `conf` / `ambiguous` / `why`。
3. `anchors` 数组写「能独立标识该 IP、且无歧义」的词。
4. **重新生成 `ip/index.json`**：把新包的 `id` + 第 3 步的 `anchors` 登记进去
   （`packages` 保持 `id` 字典序，`anchors` 逐字复制）——否则懒加载永不触发（§3）。
   `core.js` 的 `anchors` 映射表**不用动**，它只是清单失效时的回退保底。
5. 自测（可直接在页面 console 里跑，`'arknights'` 换成你的新包 id）：

```js
HS.dict.load('arknights').then(() => {
  console.log(HS.dict.loaded(), HS.dict.stats());
  ['小火龙', '叔叔', '蒂蒂'].forEach(q => {
    const r = HS.dict.lookup(q);
    console.log(q, 'active:', HS.dict.pick(r.hits, 'active', 2),
                   'low:',    HS.dict.pick(r.hits, 'low', 2));
  });
});
```

6. 想验证「某词最终会填进搜索框成什么」，看命中对象的 `hintQuery` 字段。
   若 `hintQuery` 为空，说明该 `to` 键推不出可点的词（如 `to.term`），会降级成不可点说明。
